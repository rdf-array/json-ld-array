SHACL-array is SHACL (SHACL, with the list constraints of SHACL 1.2 Core) over the rdf-array data model, in which ( … ) is one term, a sequence, and () is the empty sequence. It changes two things and adds no vocabulary:

This is a working document of the rdf-array project, generated from shacl-array.md by md-to-respec.py in the same repository. It is not a W3C document and has no standing anywhere.

Introduction

Definition, 2026-10-25. Implemented in jena-array's jena-shacl. This document is shacl-array.md in the organisation's meta-repository, rendered at <https://rdf-array.github.io/rdf-array/shacl-array.html>; rdf-array.md describes the change from RDF to rdf-array, and rdf-array#9 holds the discussion this settles.

  1. A SHACL list is a sequence term. Everywhere SHACL reads a list from the shapes graph, it reads a sequence. An rdf:first/rdf:rest ladder spelled out in triples is triples, not a list, and rdf:nil is an IRI like any other.
  2. SHACL 1.2's list constraints apply to sequence values. sh:memberShape, sh:minListLength, sh:maxListLength and sh:uniqueMembers constrain a value node that is a sequence. They are the counterpart of ShEx-array's Collection shape expression, ((shapeExpr))[min, max].

Lists in the shapes graph

These parameters take a SHACL list, which in SHACL-array is a sequence term:

ParameterIn Turtle-array
sh:path (a sequence path)sh:path ( ex:parent ex:name )
sh:alternativePathsh:path [ sh:alternativePath ( ex:father ex:mother ) ]
sh:insh:in ( "red" "green" "blue" )
sh:languageInsh:languageIn ( "en" "fr" )
sh:and, sh:or, sh:xonesh:or ( [ sh:datatype xsd:string ] [ sh:datatype rdf:langString ] )
sh:ignoredPropertiessh:ignoredProperties ( rdf:type )
SHACL 1.2 list node expressions( ex:a ex:b ), and () the empty list

Written in Turtle-array these are sequences already: the syntax is unchanged, and a shapes graph written for SHACL reads the same under SHACL-array. Three consequences:

  • A ladder is not a list. A shapes graph that spells a list as rdf:first/rdf:rest triples (in N-Triples written by an RDF 1.1 tool, say) is ill-formed where a list is expected, and a processor reports a shapes-graph error. Convert it first. A ladder read as triples is no longer special anywhere in rdf-array.
  • () is the empty list; rdf:nil is not. sh:path () is an error, as an empty sequence path was before. sh:path rdf:nil is the predicate path of the IRI rdf:nil.
  • Lists hold no blank-node structure. A shape inside a list, sh:or ( [ … ] ), is a blank node that is an element of the sequence; its own triples are ordinary triples of the shapes graph.

The same holds for what a processor writes: sh:resultPath of a sequence path is a sequence term, and SHACL compact syntax arrays (in=[ 1 2 ], | alternatives) produce sequences.

Sequence-valued data

SHACL 1.2 Core defines four constraint components for "SHACL lists" in the data graph. In SHACL-array a SHACL list in the data is a sequence term, so they constrain sequence values:

ParameterA value node conforms when it is a sequence and …
sh:memberShape Severy member conforms to the node shape S
sh:minListLength nit has at least n members
sh:maxListLength nit has at most n members
sh:uniqueMembers trueno member occurs twice (by RDF term equality); false constrains nothing

A value node that is not a sequence violates each of them. That includes an IRI, a literal, rdf:nil, and a blank node at the head of a ladder. Each violating value node gives one result: sh:value is the value node (the sequence) and sh:resultPath the path that reached it. SHACL 1.2 also lists the failing members as sh:detail; jena-array does not emit sh:detail yet.

An RGB colour, in ShEx-array ((xsd:integer MININCLUSIVE 0 MAXINCLUSIVE 255))[3]:

PREFIX ex:  <http://example/>
  PREFIX sh:  <http://www.w3.org/ns/shacl#>
  PREFIX xsd: <http://www.w3.org/2001/XMLSchema#>
  
  ex:ColourShape a sh:NodeShape ;
    sh:targetClass ex:Swatch ;
    sh:property [
      sh:path ex:rgb ;
      sh:minCount 1 ; sh:maxCount 1 ;
      sh:minListLength 3 ; sh:maxListLength 3 ;
      sh:memberShape [ sh:datatype xsd:integer ; sh:minInclusive 0 ; sh:maxInclusive 255 ]
    ] .
  
  ex:red  a ex:Swatch ; ex:rgb ( 255 0 0 ) .    # conforms
  ex:pink a ex:Swatch ; ex:rgb ( 255 192 ) .    # too short: MinListLength
  ex:blue a ex:Swatch ; ex:rgb ( 0 0 256 ) .    # 256 out of range: MemberShape

A playlist whose tracks are each a ex:Track with a title, and which never repeats a track:

ex:PlaylistShape a sh:NodeShape ;
    sh:targetClass ex:Playlist ;
    sh:property [
      sh:path ex:tracks ;
      sh:minListLength 1 ;
      sh:uniqueMembers true ;
      sh:memberShape [ sh:class ex:Track ;
                       sh:property [ sh:path ex:title ; sh:minCount 1 ] ]
    ] .

sh:minCount and sh:maxCount keep counting values: ex:rgb ( 255 0 0 ) is one value. Nested sequences are members like any other, so a polygon of points is sh:memberShape [ sh:minListLength 2 ; sh:maxListLength 2 ; sh:memberShape [ sh:datatype xsd:decimal ] ].

What SHACL-array does not add

  • No path into a sequence. SHACL property paths reach value nodes through triples, and a sequence's members are not reached through triples. sh:memberShape is the way to constrain them. SPARQL-array's position patterns (((?e))[2], [*]) have no SHACL path counterpart, and SHACL-SPARQL constraints can use them where the engine has them.
  • No positional constraints. Neither SHACL 1.2 nor SHACL-array can say "the first member is a string, the rest are integers". ShEx-array cannot say it either; it is an open question for both.
  • No new results vocabulary. A sequence value appears in a report as itself: sh:value ( 255 192 ).

Tests

data-shapes-array is the W3C SHACL 1.0 and 1.2 test suites (w3c/data-shapes) read as SHACL-array, following the rules of the other suite forks: no test deleted, expectations changed and inputs not, every changed test with an rdfs:comment "rdf-array: …". A test with nothing left to test is marked mf:status sht:rejected, the SHACL test vocabulary's status for a test not to run. Its doc/rdf-array.md has the details:

TestUnder SHACL-array
1.0 core/path/path-strange-001re-recorded: the ladder on the path node is ordinary triples, so the path is the inverse path ^ex:p
1.0 core/path/path-strange-002rejected: without the ladder only a one-member sequence path is left, which SHACL does not allow
1.0 and 1.2 core/complex/shacl-shaclshacl-shacl itself rewritten: sh:memberShape and sh:minListLength instead of rdf:rest*/rdf:first (tools/rewrite-shacl-shacl.py); the test requires ra:ShaclListConstraints
1.2 core/property/memberShape-001, maxListLength-001, uniqueMembers-001re-recorded: ladders and rdf:nil are not lists, so they violate as non-lists
1.2 core/node/memberShape-001, minListLength-001, maxListLength-001, uniqueMembers-001rejected: their focus nodes are IRIs spelled as ladders, and an IRI is never a sequence
1.2 core/node/in-003, xone-003rejected: sh:in rdf:nil and sh:xone rdf:nil make the shapes graph ill-formed
1.2 node-expr/shnex/list list-emptyre-recorded: () is a list expression with no members and outputs nothing

Its sibling data-shapes-contrib holds 21 tests no W3C suite has, in the same layout, seeded from jena-array's own: sequence paths (nested in alternative paths), rdf:nil as a predicate path, and ladders and () where a list is expected (sht:Failure). Under sh:in, sh:or, sh:languageIn and sh:ignoredProperties they hold sequences, and sh:in () and sh:xone () are the counterparts of the rejected in-003 and xone-003. The four list constraints appear on property values and on focus nodes that are sequences (the counterparts of the rejected node-level tests), together with this document's colour, playlist and polygon. Its bin/build.py takes each expectation from jena-array and requires rudof-array to agree wherever it has the feature. The vocabulary adds ra:ShaclListConstraints for tests that need the list constraints.
