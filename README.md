# rdf-array

**rdf-array** is RDF with one more kind of term, the **sequence**: `(1 2 3)` in Turtle is one term
holding three literals in order, `()` is the empty sequence, and a sequence may hold terms of any
kind, sequences included. Nothing else about RDF changes. The organisation holds forks of RDF
implementations that teach them the term, one stack per language, and this repository is its
meta-repository: the documents below and the list of the forks.

## Repositories

[Test suites](#test-suites) · [Java](#java) · [JavaScript](#javascript) · [Python](#python) ·
[Rust](#rust) · [Not yet forked](#not-yet-forked)

Every fork is named `<project>-array`, elided below, and works on its `rdf-sequences` branch, which
is its default branch. Each project a stack was forked for has a heading; the dependencies that had
to learn the term for it, pinned from the dependent fork, are quoted under it. A dependency shared
by several stacks is listed once, under the first, with the others named. Every repository has an
anchor named after it as GitHub names headings: lower case, punctuation dropped (`#jena`,
`#n3js`, `#rdf-tests-contrib`). Issues for all of them live in this repository
([issues](https://github.com/rdf-array/rdf-array/issues), titled `<repo>: …`).

### Test suites

Each W3C fork has a sibling `*-contrib` repository, laid out alike, for the shared tests no W3C
suite contains; contrib repositories are new, so they keep their full names and use `main`.

#### [rdf-tests](https://github.com/rdf-array/rdf-tests-array)

Fork of [w3c/rdf-tests](https://github.com/w3c/rdf-tests): the RDF 1.1/1.2 syntax and semantics
suites and the SPARQL 1.0/1.1/1.2 suites, expectations rewritten for sequences (40 tests changed).

> - <a id="rdf-tests-contrib"></a>[rdf-tests-contrib](https://github.com/rdf-array/rdf-tests-contrib) —
>   Turtle-, TriG-, N-Triples- and N-Quads-array tests and SPARQL-array evaluation, update, syntax
>   and results tests.

#### [json-ld-api](https://github.com/rdf-array/json-ld-api-array)

Fork of [w3c/json-ld-api](https://github.com/w3c/json-ld-api): the JSON-LD 1.1 API suite with
`@list` as one sequence.

> - <a id="json-ld-api-contrib"></a>[json-ld-api-contrib](https://github.com/rdf-array/json-ld-api-contrib) —
>   toRdf and fromRdf tests for sequences and the JSON-LD-array tests.

#### [json-ld-streaming](https://github.com/rdf-array/json-ld-streaming-array)

Fork of [w3c/json-ld-streaming](https://github.com/w3c/json-ld-streaming): the JSON-LD streaming
suite with `@list` as one sequence; its contrib tests are in json-ld-api-contrib.

#### [shexTest](https://github.com/rdf-array/shexTest-array)

Fork of [shexSpec/shexTest](https://github.com/shexSpec/shexTest): the ShEx suite with Collection
shape expressions in place of ladder shapes, ShExR.shex included.

> - <a id="shextest-contrib"></a>[shexTest-contrib](https://github.com/rdf-array/shexTest-contrib) —
>   Collection schemas (ShExC, ShExJ, ShExR), validation and negative syntax tests.

#### [rdf-test-suite](https://github.com/rdf-array/rdf-test-suite-array)

Fork of [rubensworks/rdf-test-suite.js](https://github.com/rubensworks/rdf-test-suite.js): the
manifest runner of the JavaScript forks, reading expectations that hold `( … )` (stock

One thing that is not an implementation ranks above most of these: a converter between ladders and
sequences, without which rdf-array data cannot meet RDF 1.1 systems. The conformance suite that
ranked beside it is done: the [`*-contrib` repositories](#test-suites), which
jena, comunica, N3.js, shex.js, jsonld.js, rdflib, PyShEx, oxigraph and rudof run.

Not targets ([why](targets.md#not-targets)): Raptor and Redland; Virtuoso, GraphDB, Stardog,
AllegroGraph, Neptune, Blazegraph.

## Skills and tools

The formula the forks follow is written down as skills, in `.claude/skills/`, for the sessions
that make the next ones:

- [fork-array](.claude/skills/fork-array/SKILL.md): forking a project into the organisation and
  teaching it the term, layer by layer, with the naming, remotes, banner, notes, pinning and Pages
  conventions.
- [array-tests](.claude/skills/array-tests/SKILL.md): transforming a project's tests, flagging the
  ladder-dependent ones, folding ladder expectations into sequences with
  [tools/rewrite-ladders.py](tools/rewrite-ladders.py), and the cases every fork must pass.
- [w3c-test-suites](.claude/skills/w3c-test-suites/SKILL.md): which W3C and community suites apply,
  what rdf-array changes in each, how to fork them as `<suite>-array`, and how each implementation
  runs them.
- [readme-manifest](.claude/skills/readme-manifest/SKILL.md): keeping the repository list above in
  step with GitHub, checked by [tools/manifest-check.py](tools/manifest-check.py).

## Conventions

A fork's README opens with a banner, "`<project>-array`: `<project>` for rdf-array", beside an icon
that puts the original's avatar between big `[` `]` brackets; its notes live in `doc/rdf-array.md`;
its commit messages start with `rdf-array:` (older ones with `RDF-:`); a test that depends on
`rdf:first`/`rdf:rest` ladders is flagged with the reason, never silently dropped. The rest is in
[rdf-array.md](rdf-array.md).
