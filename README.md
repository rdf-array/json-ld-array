# rdf-array

**rdf-array** is RDF with one more kind of term, the **sequence**: `(1 2 3)` in Turtle is one term
holding three literals in order, `()` is the empty sequence, and a sequence may hold terms of any
kind, sequences included. Nothing else about RDF changes. The organisation holds forks of RDF
implementations that teach them the term, one stack per language, and this repository is its
meta-repository: the documents below, the list of the forks and every repository's issues.

## Repositories

**[repos.html](https://rdf-array.github.io/rdf-array/repos.html)** lists every repository of the organisation by language and stack, with its
upstream, what it changes, the forked dependencies a stack reaches, the test suites it runs, its open
issues, and the targets not yet forked. It renders [repos.json](repos.json), which
[tools/manifest-check.py](tools/manifest-check.py) checks against GitHub and against each fork's
build files.

Every fork is named `<project>-array` and works on its `rdf-sequences` branch, its default branch.
The stacks, each named for the project it was forked for:

- **Java:** [jena](https://rdf-array.github.io/rdf-array/repos.html#jena) — Turtle-array, SPARQL-array, ShEx-array, SHACL-array.
- **JavaScript:** [shex.js](https://rdf-array.github.io/rdf-array/repos.html#shexjs) (with N3.js) — ShEx-array in the browser and Node;
  [comunica](https://rdf-array.github.io/rdf-array/repos.html#comunica) (with traqula and the RDF/JS libraries) — the SPARQL-array engine;
  [jsonld.js](https://rdf-array.github.io/rdf-array/repos.html#jsonldjs) — JSON-LD-array.
- **Python:** [PyShEx](https://rdf-array.github.io/rdf-array/repos.html#pyshex) (with rdflib) — ShEx-array over RDFLib.
- **Rust:** [oxigraph](https://rdf-array.github.io/rdf-array/repos.html#oxigraph) — the store, its syntaxes and SPARQL-array;
  [rudof](https://rdf-array.github.io/rdf-array/repos.html#rudof) — ShEx-array and SHACL lists.
- **Test suites:** [the W3C suite forks and their `*-contrib` siblings](https://rdf-array.github.io/rdf-array/repos.html#test-suites), and
  rdf-test-suite, the JavaScript forks' runner.

[Not yet forked](https://rdf-array.github.io/rdf-array/repos.html#not-yet-forked), assessed in [targets.md](targets.md).

## Issues

Issues for every repository live [here](https://github.com/rdf-array/rdf-array/issues), and
[repos.html](https://rdf-array.github.io/rdf-array/repos.html#issues) shows each one with its repository. A title starts with the repository it is
about, `<repo>: …` (`rudof-array: …`), and the issue is labelled `repo`. An issue spanning
repositories is labelled `cross-repo`, and its body may open with a `Repos: a, b` line. One about
rdf-array itself, the data model or an -array specification, is labelled `spec`. Add
`open-question`, `bug` or `enhancement` as they apply.

## Skills and tools

The formula the forks follow is written down as skills, in `.claude/skills/`, for the sessions
that make the next ones:

- [fork-array](.claude/skills/fork-array/SKILL.md): forking a project into the organisation and
  teaching it the term, layer by layer, with the naming, remotes, banner, notes, pinning and Pages
  conventions.
- [array-tests](.claude/skills/array-tests/SKILL.md): transforming a project's tests, flagging the
  ladder-dependent ones, folding ladder expectations into sequences with
  [tools/rewrite-ladders.py](tools/rewrite-ladders.py), and the cases every fork must pass.
- [w3c-test-suites](.claude/skills/w3c-test-suites/SKILL.md): which W3C and community suites apply,
  what rdf-array changes in each, how to fork them as `<suite>-array`, and how each implementation
  runs them.
- [repos-manifest](.claude/skills/repos-manifest/SKILL.md): keeping [repos.json](repos.json) in step
  with GitHub and the forks, checked by [tools/manifest-check.py](tools/manifest-check.py), and
  filing issues.

## Conventions

A fork's README opens with a banner, "`<project>-array`: `<project>` for rdf-array", beside an icon
that puts the original's avatar between big `[` `]` brackets; its notes live in `doc/rdf-array.md`;
its commit messages start with `rdf-array:` (older ones with `RDF-:`); a test that depends on
`rdf:first`/`rdf:rest` ladders is flagged with the reason, never silently dropped. The rest is in
[rdf-array.md](rdf-array.md).
